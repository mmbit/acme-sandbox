# Memory: what we keep, and what we look up


Every job and call starts from what agents wrote down: profiles, the CEO's page, decisions, notes. What's stored and
no longer true comes back into every job that reads it. So we keep two kinds of thing apart.

## What goes in memory

- **Rules from the board.** They stay until the board changes them (a later call, card or decision that replaces one).
- **What you learned about doing the work** that still holds: a method, a trap and its way round, where something is
  looked up. Lasting knowledge others need goes in a note or playbook (the Knowledge playbook); your memory points to it.
- **What you're in the middle of**, until it's done.

## What never goes in memory

**Beliefs about how the system behaves**: how long reviews take, what holds work up, how fast a tool is, who answers
when, how full the seats are. They change with every process change and are soon wrong. Look them up live when a
question needs them (`hq report`, `hq estimate`, `hq search`, the note that measures it), and store at most where to
look.

## Keeping it true

- **At the end of every job**, rewrite your working memory to what's true now, rather than adding to it: a line that
  this job made false goes. The CEO's lessons live on its page (`hq pad`), its profile's working memory one line
  pointing there.
- **Once a week**, each agent's memory pass (`shared/routines/memory.md`) rereads the whole of it against how things
  work now, and marks its decisions a later one replaced ("Replaced <date> by …"), which stay as history.
- **No size limit.** A cap cuts what's true with what's stale; the weekly pass does the pruning.

Old calls, decisions and track records are history: never rewritten, only marked when replaced.
